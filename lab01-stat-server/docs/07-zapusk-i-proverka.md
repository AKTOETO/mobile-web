# 7. Запуск, конфигурация, тесты, демонстрация

## Требования

- Node.js 18 или новее (проверено на v26.10.0). Проверка: `node --version`.
- Интернет не нужен: сервер и клиент не используют внешних библиотек.
- Для `npm run test:ui` нужен `jsdom` (единственная dev-зависимость, уже в `package.json`).

## Запуск

```bash
cd lab01-stat-server
npm start            # = node server/server.js
```

В консоли появится:

```
Сервер статистики запущен
  На этом ПК:       http://localhost:3000/
  Дашборд:          http://localhost:3000/dashboard.html
  В локальной сети: http://192.168.1.15:3000/   (wlan0)
  Файл статистики:  …/lab01-stat-server/data/stats.json
Остановка: Ctrl+C
```

Другие режимы:

```bash
npm run dev          # node --watch — автоперезапуск при изменении серверного кода
npm run seed         # наполнить статистику демо-данными (24 посетителя, 7 дней)
npm run reset        # очистить data/stats.json
SEED_ON_START=1 npm start   # если данных ещё нет — сразу наполнить их демоном
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `0.0.0.0` | интерфейс прослушивания; `0.0.0.0` нужен для доступа с телефона |
| `PORT` | `3000` | порт HTTP-сервера |
| `DATA_DIR` | `lab01-stat-server/data` | папка с `stats.json` |
| `DATA_FILE` | `data/stats.json` | явный путь к файлу статистики |
| `SESSION_TIMEOUT_SEC` | `1800` | перерыв, после которого сессия считается закрытой |
| `HEARTBEAT_SEC` | `30` | период продления сессии клиентом |
| `MAX_EVENTS` | `20000` | лимит «сырых» событий в файле |
| `MAX_SESSIONS` | `5000` | лимит записей сессий |
| `MAX_FEEDBACK` | `500` | лимит сообщений формы |
| `SAVE_DEBOUNCE_MS` | `400` | частота записи на диск |
| `MAX_BODY_BYTES` | `65536` | максимальный размер тела POST |
| `SEED_ON_START` | — | `1` — сгенерировать демо-данные при пустой базе |

Пример: `PORT=8080 SESSION_TIMEOUT_SEC=300 npm start`.

## Тесты

### Интеграционный тест API (без зависимостей)

```bash
npm test
```

Скрипт `test/api-test.js` сам поднимает сервер на порту `3111` во временной папке `test/tmp-data/`,
затем выполняет 33 проверки: раздача статики, `404` для неизвестного пути, приём `pageview`,
уникальные посетители, клики (`action`), `heartbeat`, `session_end` и длительность сессии,
обработка формы (успех и `422`), CSV-экспорт, диапазоны `24h`/`7d`/`all`, сохранение на диск,
сброс, битый JSON (`400`), неизвестный метод (`404`).

### Тест интерфейса в jsdom

```bash
npm install          # ставит jsdom (dev-зависимость)
npm run test:ui
```

`test/frontend-smoke.js` поднимает сервер и в эмуляции браузера (jsdom) проверяет 16 сценариев:
JS получил идентификаторы посетителя/сессии, живой блок главной заполнен ответом API,
клик по кнопке с `data-track` отправил событие, фильтр каталога работает без перезагрузки,
форма обратной связи отправлена асинхронно и её ошибки показаны на странице,
дашборд заполнил KPI, инициализировал 4 canvas-графика, таблицу сессий, список страниц,
кнопки «Демо-данные», «Сбросить» и выбор периода.

Оба теста завершают сервер и возвращают код 0 при успехе / 1 при падении любой проверки.
Порты тестов можно переопределить, если они заняты: `TEST_PORT=4111 npm test`.

## Пошаговый сценарий демонстрации (5–7 минут)

1. **Подготовка:** `npm run seed` → открыть `http://localhost:3000/dashboard.html`,
   показать, что графики уже наполнены (это «до»).
2. **Новый посетитель:** открыть сайт в режиме инкогнито (или другом браузере) —
   `http://localhost:3000/`. Перейти в **Каталог**, применить фильтр (цена 20000, категория «смартфоны»),
   нажать «Сбросить», затем «Показать ещё».
3. **Форма:** на **Обратной связи** сначала отправить некорректную форму (имя из 1 символа) —
   показать серверную валидацию (`422` и список ошибок), затем корректную — сообщение появится в таблице.
4. **Аналитика:** вернуться на дашборд → «Обновить» → показать, что просмотры и уникальный
   посетитель выросли, в таблице сессий появилась открытая сессия (`открыта`),
   в блоке «Источники переходов» виден внутренний переход.
5. **Длительность сессии:** оставить вкладку открытой ~1–2 минуты, нажать «Обновить» —
   длительность открытой сессии растёт (heartbeat). Закрыть вкладку, обновить дашборд —
   сессия закрыта и зафиксирована её длительность.
6. **Периоды и фильтр:** выбрать «7 дней» и конкретную страницу — KPI и графики пересчитываются.
7. **Экспорт:** «Экспорт CSV» → открыть файл в Excel/LibreOffice.
8. **Сохранение данных:** `Ctrl+C`, снова `npm start`, открыть дашборд — статистика на месте.
9. **Адаптивность:** сузить окно браузера (или открыть в эмуляции телефона) — меню сворачивается,
   графики и формы перестраиваются.
10. **Телефон (Аврора):** открыть адрес из строки «В локальной сети» (см. `docs/08-aurora.md`).

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `EADDRINUSE: address already in use :::3000` | порт занят другим процессом: `PORT=8080 npm start` или найти процесс (`ss -ltnp \| grep 3000`) |
| Телефон не открывает страницу | сервер слушает не `0.0.0.0` (проверить `HOST`), телефон в другой сети, закрыт порт файрволом (`sudo ufw allow 3000/tcp`) |
| Графики пустые | нет данных за выбранный период → «Демо-данные» или период «всё время» |
| `npm run test:ui` не найден модуль `jsdom` | выполнить `npm install` |
| Статистика «исчезла» | удалён `data/stats.json` (он в `.gitignore`) или нажата кнопка «Сбросить» |
