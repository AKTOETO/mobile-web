## Как появляются посетитель и сессия

| Понятие | Как определяется |
|---|---|
| **Посетитель** | `visitorId`, который браузер хранит в `localStorage` (ключ `weblab.visitorId`). Не зависит от cookies сервера. |
| **Сессия** | `sessionId` из `sessionStorage` (ключ `weblab.sessionId`). Живёт до закрытия вкладки; при повторном открытии сайта — новая сессия. |
| **Конец сессии** | Событие `session_end` от клиента ИЛИ перерыв в событиях больше `SESSION_TIMEOUT_SEC` (по умолчанию 1800 с = 30 мин). |
| **Новый визит того же посетителя** | Новая запись в `sessions`; если клиент прислал уже занятый `sessionId`, сервер создаёт идентификатор вида `sessionId#visits-N`. |

## Формулы показателей

Обозначения: окно наблюдения `[from, now]` задаётся параметром `range`
(`24h`, `7d`, `30d`, `all`), дополнительно возможен фильтр по странице `page`.

| Показатель | Формула |
|---|---|
| Просмотры страниц | число событий `type = pageview` в окне (с учётом фильтра по странице) |
| Уникальные посетители | число различных `visitorId` среди событий окна |
| Сессии | сессии, у которых `start` или `lastEvent` попадает в окно |
| Открытые сессии | сессии окна с `closed = false` (клиент ещё «на сайте») |
| Новые посетители | посетители окна, у которых `firstSeen ≥ from` |
| Вернувшиеся посетители | посетители окна, у которых `visits > 1` |
| Длительность сессии | `end − start` для закрытых; для открытых `min(lastEvent − start, SESSION_TIMEOUT_SEC)`; результат в секундах |
| Средняя длительность сессии | среднее арифметическое длительностей сессий окна |
| Максимальная длительность | `max(durationSec)` по сессиям окна |
| Глубина просмотра | `просмотры / сессии` (округление до 0.01) |
| Показатель отказов | `сессии с pageViews ≤ 1 / все сессии × 100 %` |
| На сайте сейчас | посетители, у которых `now − lastSeen ≤ 5 мин` |
| Нажатия кнопок | число событий `type = action` в окне |
| Популярные страницы | группировка `pageview` по `page`: `views` и число различных посетителей |
| Устройства | группировка сессий по `device` (определяется по User-Agent) |
| Источники переходов | по `referrer` первой страницы сессии: пусто → «прямые», хост `referrer` = хост страницы (`origin`) → «внутри сайта», иначе внешний хост |
| `lifetime.*` | те же показатели по всем данным, без фильтра по диапазону |

## Классификация устройств (`server/storage.js`, `detectDevice`)

| Категория | Признак в User-Agent |
|---|---|
| `aurora` | `aurora`, `sailfish`, `jolla` |
| `tablet` | `ipad`, `tablet`, `playbook`, `silk` |
| `mobile` | `mobi`, `android`, `iphone`, `ipod`, `windows phone`, `blackberry`, `nokia` |
| `bot` | `bot`, `crawl`, `spider`, `curl`, `python`, `wget`, `node-fetch` |
| `desktop` | всё остальное |

Пример User-Agent устройства под управлением Аврора, который попадает в категорию `aurora`:

```
Mozilla/5.0 (Linux; U; Android 8.1.0; ru-ru; Jolla X) AppleWebKit/537.36 (KHTML, like Gecko) Version/2.0 Mobile Safari/537.36 Aurora Browser/2.0.0.21
```

## Временные ряды для графика

| `range` | Размер корзины | Подпись на оси X |
|---|---|---|
| `24h` | 1 час | `13:00` |
| `7d` | 6 часов | `13:00` |
| `30d` | 1 день | `12.10` |
| `all` | 1 день | `12.10` |

В каждой корзине считаются `views` (просмотры) и `visitors` (различные посетители) —
по ним строятся две линии на графике «Просмотры по времени».

## Лимиты и ротация данных

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `MAX_EVENTS` | 20000 | старше новых события удаляются из начала массива (массив всегда отсортирован по времени) |
| `MAX_SESSIONS` | 5000 | удаляются самые старые **закрытые** сессии |
| `MAX_FEEDBACK` | 500 | старые сообщения формы удаляются |
| `SAVE_DEBOUNCE_MS` | 400 | как часто накопленные изменения пишутся на диск |

Счётчик `counters.trimmedEvents` показывает, сколько событий было удалено, —
суммарные `counters.pageViews` при этом не уменьшаются.
