# 8. Демонстрация в локальной сети и на телефоне с Аврора

## Почему это работает «в локальной сети»

Сервер слушает `0.0.0.0` (значение по умолчанию в `server/config.js`), то есть принимает
соединения на всех сетевых интерфейсах машины. При старте печатается список IPv4-адресов:

```
В локальной сети: http://192.168.1.15:3000/   (wlan0)
```

Никакого публичного хостинга не требуется — достаточно Wi-Fi сети, к которой подключены
ноутбук (сервер) и телефон.

## Пошагово

1. **Узнать адрес сервера.** Запустить `npm start` и посмотреть строку «В локальной сети»,
   либо выполнить:
   ```bash
   # Linux
   ip -4 addr show scope global | grep inet
   # Windows
   ipconfig | findstr IPv4
   ```
2. **Разрешить порт в брандмауэре** (если он включён):
   ```bash
   sudo ufw allow 3000/tcp        # Ubuntu
   # Windows: «Брандмауэр Защитника Windows» → создать правило для входящего TCP 3000
   ```
3. **Подключить телефон к той же Wi-Fi сети** (важно: не к гостевой сети с изоляцией клиентов).
4. **Открыть в браузере телефона** адрес вида `http://192.168.1.15:3000/`.
   Страница статистики: `http://192.168.1.15:3000/dashboard.html`.
5. **Проверить, что визит с телефона попал в статистику:** на дашборде (с ПК) в блоке
   «Устройства посетителей» появится сектор **aurora**, а в таблице сессий — строка с устройством `aurora`.
   Определение выполнено по User-Agent в `server/storage.js` (`detectDevice`), ключевые слова:
   `aurora`, `sailfish`, `jolla`.

## Особенности браузера Аврора (Sailfish OS)

| Особенность | Как учтено в решении |
|---|---|
| Движок WebKit с поддержкой ES-возможностей старого уровня | в клиентском JS нет optional chaining (`?.`), `??`, классовых полей; только `var`, функции, `Promise`, `async/await` |
| `crypto.randomUUID()` может отсутствовать | генерация идентификатора посетителя с проверкой наличия и резервным вариантом на `Math.random` |
| `navigator.sendBeacon` поддерживается не во всех версиях | `session_end` отправляется через `sendBeacon`, а при его отсутствии — через `fetch` с `keepalive: true` |
| Нет внешних CDN и библиотек (офлайн-режим, экономия трафика) | сервер и клиент не используют npm-зависимостей и интернет-ресурсов; шрифты системные |
| Экран небольшого размера, разное соотношение сторон | адаптивная вёрстка: `@media (max-width: 768px)` и `(max-width: 480px)`, кнопки и поля на всю ширину, таблицы со горизонтальным скроллом, canvas высотой 200–220 px |
| Браузер может ограничивать `localStorage` в приватном режиме | код не падает: идентификаторы создаются в памяти, статистика продолжает собираться |
| HTTP вместо HTTPS | сервер работает по HTTP; в локальной сети это нормально. При необходимости можно включить самоподписанный сертификат (см. `docs/09-faq.md`) |

## Что показать на телефоне

1. Открыть главную страницу — меню свёрнуто в кнопку «Меню», KPI-блок заполнен числами с сервера.
2. Пройти **Каталог → О проекте → Обратная связь** (видно, как меняются просмотры).
3. Нажать «Применить фильтр» в каталоге — список изменится без перезагрузки (JS-обработка кнопки).
4. Отправить форму обратной связи с телефона — сообщение появится в таблице на сервере.
5. Открыть `dashboard.html` на телефоне: графики перестроены в одну колонку,
   в диаграмме устройств виден сектор **aurora**.
6. Показать тот же дашборд на ПК — один и тот же сервер и одна база статистики.

## Если телефон не подключается

| Проверка | Команда / действие |
|---|---|
| Сервер слушает все интерфейсы | в выводе запуска должна быть строка «В локальной сети»; `ss -ltnp \| grep 3000` покажет `0.0.0.0:3000` |
| Порт не закрыт файрволом | `sudo ufw status`, временно `sudo ufw allow 3000/tcp` |
| Телефон и ПК в одной подсети | `ping 192.168.1.15` с телефона (если сеть разрешает ICMP) |
| Гостевая сеть Wi-Fi изолирует клиентов | переключиться на основную сеть или использовать точку доступа на ноутбуке |
| Порт 3000 блокируется политикой сети | `PORT=8080 npm start` (порты 8080/8000 обычно открыты) |
| Телефон в режиме «только IPv6» | убедиться, что в выводе сервера IPv4-адрес, и использовать его |
