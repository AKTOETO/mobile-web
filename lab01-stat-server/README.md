# Лабораторная работа №1 — сервер статистики аналитики сайта (вариант 7)

## Что это

Учебное веб-приложение: **демонстрационный сайт + сервер, который собирает и визуализирует
статистику посещений**.

Сервер на **Node.js (только встроенные модули, без npm-зависимостей)** принимает от браузера
асинхронные события и считает:

- количество просмотров страниц;
- уникальных посетителей;
- сессии и их длительность;
- глубину просмотра, показатель отказов, устройства (в т.ч. Аврора/Sailfish), источники переходов.

Дашборд `/dashboard.html` показывает эти данные в виде **графиков на `<canvas>`**
(временная линия, столбцы страниц, кольцевая диаграмма устройств, длительность сессий).

## Зачем это

По заданию нужно показать взаимодействие сервера с web-клиентом: JS-обработка кнопок формы,
асинхронные вызовы (`async/await`, `Promise`, `fetch`), адаптивная вёрстка через `@media`
и запуск в локальной сети (доступ с ПК и с телефона под управлением Аврора).

## Как запустить

Нужен Node.js 18+ (проверить: `node --version`).

```bash
cd lab01-stat-server
npm start                 # или: node server/server.js
```

Сервер сам напечатает адреса:

```
На этом ПК:       http://localhost:3000/
Дашборд:          http://localhost:3000/dashboard.html
В локальной сети: http://192.168.1.15:3000/   (wlan0)
```

Другие полезные команды:

```bash
npm run dev               # запуск с автоперезапуском при правках (node --watch)
npm run seed              # наполнить статистику демонстрационными данными (24 посетителя за 7 дней)
npm run reset             # очистить статистику
npm test                  # интеграционный тест API (33 проверки, сервер поднимается сам)
npm run test:ui           # тест интерфейса в jsdom (нужен npm install)
```

Параметры задаются переменными окружения: `PORT=8080 HOST=0.0.0.0 SESSION_TIMEOUT_SEC=1800 npm start`.

## Как проверить (мини-демонстрация)

1. `npm run seed` — чтобы графики сразу были наполнены.
2. Открыть `http://localhost:3000/` → пройтись по страницам **Каталог → О проекте → Обратная связь**.
3. На **Обратной связи** нажать «Отправить» (страница не перезагружается, сообщение уходит `POST /api/feedback`).
4. Открыть `http://localhost:3000/dashboard.html`:
   - KPI-плитки: просмотры, уникальные посетители, сессии, средняя длительность;
   - 4 графика;
   - кнопки формы отчёта: **Применить**, **Обновить**, **Демо-данные**, **Экспорт CSV**, **Сбросить**;
   - включённое автообновление каждые 5 секунд.
5. Проверить адаптивность: сузить окно браузера — меню свернётся в кнопку «Меню»,
   графики и формы перестроятся (правила `@media` в `public/css/style.css`).
6. Проверить сохранение данных: остановить сервер (`Ctrl+C`), снова запустить — статистика останется
   в `data/stats.json`.
7. Телефон (Аврора): подключиться к той же Wi-Fi сети и открыть адрес из строки «В локальной сети».

## Структура

```
lab01-stat-server/
├── server/          серверная часть (Node.js)
│   ├── server.js    HTTP-сервер, маршрутизация, API, раздача html/css/js
│   ├── storage.js   хранение статистики в data/stats.json (атомарная запись)
│   ├── analytics.js расчёт показателей и данных для графиков
│   ├── seed.js      генератор демонстрационных данных
│   ├── seed-cli.js  CLI: npm run seed / npm run reset
│   └── config.js    настройки (порт, таймауты, лимиты)
├── public/          клиентская часть (отдаётся браузеру)
│   ├── index.html catalog.html about.html contact.html dashboard.html
│   ├── favicon.svg
│   ├── css/style.css css/dashboard.css   (адаптивная вёрстка, @media)
│   └── js/api.js tracker.js charts.js dashboard.js app.js
├── test/            api-test.js (33 проверки), frontend-smoke.js (16 проверок в jsdom)
├── docs/            подробная документация
├── report/          материалы отчёта: схемы, графики, скриншоты и их исходники
├── REPORT.md        отчёт по лабораторной работе (текст, таблицы, графики, скриншоты)
└── data/            stats.json — база статистики (создаётся автоматически)
```

## Отчёт

[REPORT.md](REPORT.md) — ход решения, таблицы соответствия заданию, схемы, графики по реальным
данным и скриншоты приложения (десктоп и мобильный браузер).

Все материалы воспроизводятся командами (исходники лежат в `report/src/`):

```bash
bash report/src/plantuml/render.sh                 # схемы PlantUML -> report/images/*.png
python3 report/src/python/make_charts.py           # графики matplotlib из data/stats.json
node report/src/screenshots/capture.js             # скриншоты (нужен Chrome/Chromium)
bash report/src/screenshots/prepare-for-report.sh  # уменьшение скриншотов для встраивания
bash report/src/build-docx.sh                      # REPORT.md -> HTML -> DOCX (LibreOffice)
```

DOCX собирается без pandoc: Markdown → HTML (модуль Python `markdown`) → DOCX через LibreOffice,
затем `report/src/docx-embed-images.py` встраивает картинки в файл DOCX (иначе LibreOffice
оставляет на них внешние ссылки). Готовый файл: `report/build/report.docx`.
