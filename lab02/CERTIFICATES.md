# HTTPS при смене IP и установка CA на Аврору

## Нативное приложение: установка сертификата не нужна

CA сервера встроен в RPM через `aurora-app/certs/ca.crt` и `resources.qrc`.
Приложение доверяет **только этому CA**, проверяет цепочку и срок действия
сертификата. Из TLS-ошибок допускается только несовпадение имени/адреса
(`HostNameMismatch`), поскольку сервер может получать новый IP.
Чужой CA, просроченный сертификат и остальные TLS-ошибки не игнорируются.
Для этого поведения установите заново собранную версию приложения.
RPM `x86_64` предназначен для эмулятора; для физического телефона соберите
пакет под архитектуру его процессора и соответствующую цель Aurora SDK.
Этот CA должен использоваться только для сервера инвентаря: любой сервер,
которому выдали сертификат этим CA, будет доверенным для приложения.

После смены IP компьютера достаточно изменить URL в настройках приложения,
например на `https://192.168.1.45:8443`. Телефон должен иметь сетевой доступ
к этому адресу; сервер должен слушать `0.0.0.0`, порт 8443 должен быть доступен.
`10.0.2.2` — адрес хоста только для эмулятора VirtualBox, не для телефона.

Выдать стандартный сертификат «на любой IP» нельзя: IP в SAN перечисляются
явно, маска/диапазон IP не поддерживаются. Для браузера правильное решение —
постоянное DNS-имя в SAN и подключение по этому имени. DNS при этом должен
обновляться вслед за IP. Простое добавление имени в сертификат не создаёт DNS.
Для приложения привязку к IP заменяет описанное выше доверие к выделенному CA.

## Перевыпуск серверного сертификата без смены CA

Из корня репозитория:

```bash
(cd lab02/inventory-server && bash tools/gen-cert.sh)
```

Скрипт сохраняет существующие `ca.crt` и `ca.key`, а сертификат сервера
перевыпускает с текущими IPv4-адресами, `localhost`, `inventory.local`
и `10.0.2.2` в SAN. После этого перезапустите сервер.
Приложение пересобирать и CA на устройствах переустанавливать не требуется.
Для приложения при одной лишь смене IP перевыпуск вообще не нужен;
он нужен браузеру при подключении по новому IP.

Не удаляйте CA при обычной смене IP. Храните резервную копию пары
`ca.crt`/`ca.key` в защищённом месте. Если CA всё-таки заменён, нужно обновить
`aurora-app/certs/ca.crt`, пересобрать и установить RPM, а также переустановить
CA в системном хранилище устройств, где используется браузер.
На устройство передаётся **только `ca.crt`**, никогда `ca.key` или `server.key`.

## Установка CA в систему по SSH (для браузера и curl)

Выполняйте команды на ПК из корня репозитория. На физическом телефоне
включите режим разработчика и SSH, узнайте адрес устройства и используйте
учётную запись, которой разрешено административное управление.
Следующий пример использует `defaultuser` и `sudo`; на конкретном устройстве
способ получения прав администратора может отличаться.

```bash
# Физический телефон: замените адрес на IP телефона.
DEVICE=192.168.1.50
SSH_PORT=22

# Для эмулятора вместо двух строк выше:
# DEVICE=127.0.0.1
# SSH_PORT=2223

scp -P "$SSH_PORT" lab02/inventory-server/certs/ca.crt \
    "defaultuser@$DEVICE:/tmp/mai-lab02-inventory-ca.crt"

ssh -t -p "$SSH_PORT" "defaultuser@$DEVICE" \
    'sudo install -m 0644 /tmp/mai-lab02-inventory-ca.crt /etc/pki/ca-trust/source/anchors/mai-lab02-inventory-ca.crt && sudo update-ca-trust'
```

Для эмулятора при необходимости добавьте `-i ~/AuroraOS/vmshare/ssh/private_keys/sdk`
к `scp` и `ssh` либо используйте настроенный SSH-алиас `aurora-emu`.
Закройте и снова запустите браузер после установки CA.

Проверка из SSH-сессии на устройстве (подставьте IP **сервера**):

```bash
curl https://192.168.1.45:8443/api/v1/health
```

`curl` должен работать без `-k` и без `--cacert`. Если ошибка говорит о
несовпадении имени/IP, доверие к CA не исправляет её: перевыпустите сертификат
с текущим IP скриптом выше и перезапустите сервер или подключайтесь по
постоянному DNS-имени, которое есть в SAN.

Если SSH недоступен, можно передать `ca.crt` через USB в каталог загрузок,
а затем в терминале устройства с административными правами выполнить те же
`install` и `update-ca-trust`, указав фактический путь к скачанному файлу.
Одного открытия файла сертификата в браузере недостаточно для гарантированной
установки в системное хранилище Авроры.

Удаление установленного CA (в SSH-сессии на устройстве):

```bash
sudo rm /etc/pki/ca-trust/source/anchors/mai-lab02-inventory-ca.crt
sudo update-ca-trust
```

Встроенное в приложение доверие не зависит от системного хранилища.
