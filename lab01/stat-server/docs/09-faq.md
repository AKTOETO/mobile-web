# 9. Вопросы комиссии, ограничения, направления развития

## Вероятные вопросы и короткие ответы

**Почему Node.js, а не Python/Java?**
Задание разрешает любой язык. Node.js выбран потому, что сервер и клиент говорят на одном языке,
а сервер собран только из встроенных модулей (`http`, `fs`, `path`, `crypto`, `os`) —
приложение запускается офлайн одной командой и переносится на любой ПК без установки пакетов.

**Как сервер «видит» уникального посетителя без cookies?**
Идентификатор создаётся на клиенте (`crypto.randomUUID()`), хранится в `localStorage` и передаётся
в теле каждого события. Сервер не выдаёт cookies, поэтому счёт независим от cookie-политики браузера.
Минус такой схемы очевиден: очистка хранилища браузера создаст «нового» посетителя.

**Что считается сессией и как измеряется её длительность?**
Сессия = последовательность событий одного посетителя с одним `sessionId` (хранится в `sessionStorage`).
Она открывается первым событием и закрывается либо событием `session_end` (закрытие вкладки),
либо сервером — если между событиями прошло больше `SESSION_TIMEOUT_SEC` (30 минут).
Длительность = `end − start`; для ещё открытой сессии берётся `min(lastEvent − start, таймаут)`.
Пока страница открыта, клиент каждые 30 с шлёт `heartbeat`, поэтому длительность соответствует
реальному времени просмотра, а не «последнему клику».

**Где именно асинхронный вызов JS?**
`public/js/api.js` (`async function request` + `fetch` + `AbortController`),
`public/js/tracker.js` (`await postJson(...)`, `sendBeacon`, очередь повторной отправки на `Promise`),
`public/js/dashboard.js` и `public/js/app.js` (`await Api.getStats`, `await Api.postFeedback`).
Ни одна кнопка формы не перезагружает страницу: обработчик вызывает `event.preventDefault()`.

**Почему графики на canvas, а не через Chart.js?**
В задании нужен собственный web-интерфейс и работа в локальной сети; внешние библиотеки
потребовали бы CDN или npm-установку на демо-машине. `charts.js` (~250 строк) рисует линейный график,
столбцы и кольцевую диаграмму стандартными средствами 2D-canvas, включая учёт `devicePixelRatio`.

**Как хранятся данные и почему не боитесь потерять файл?**
Один JSON-файл `data/stats.json`. Запись выполняется пачкой (debounce 400 мс) и атомарно:
сначала во временный файл, затем `fs.rename`. При `Ctrl+C` сервер делает принудительный `flush()`.
Для учебной задачи этого достаточно; для промышленной версии нужен SQL-хранилище (см. ниже).

**Что будет, если статистика станет очень большой?**
Работают лимиты: `MAX_EVENTS = 20000`, `MAX_SESSIONS = 5000`, `MAX_FEEDBACK = 500`.
События хранятся отсортированными по времени, поэтому удаляются именно самые старые,
а суммарные счётчики (`counters.pageViews` и т. д.) не теряются; количество удалённых событий
видно в `counters.trimmedEvents`.

**Как учитываются посетители, которые ничего не нажали?**
Достаточно одного `pageview`: такой визит попадает в показатель отказов (`bounceRate`)
и в «глубину просмотра» (1 страница на сессию).

## Ограничения решения (честно)

1. **Нет аутентификации дашборда** — любой в локальной сети может открыть статистику и нажать «Сбросить».
   Для учебной демонстрации это принято осознанно; в реальной системе нужен вход и права.
2. **Идентификация по клиентскому ID** не устойчива: очистка `localStorage`, другой браузер,
   приватный режим → новый «уникальный» посетитель. Классическая альтернатива — cookie с сервера.
3. **Хранение в JSON** удобно для демонстрации, но не даёт индексов: расчёт показателей —
   проход по событиям и сессиям (при 20 000 событий это доли миллисекунд, но масштабировать
   такую схему нельзя).
4. **Нет агрегации по дням в базе** — ряд для графика строится «на лету» из событий.
5. **Нет HTTPS** — в локальной сети это не критично, но форма обратной связи передаётся открытым текстом.
6. **Определение устройства по User-Agent** устаревает (UA сокращаются); надёжнее —
   `navigator.userAgentData` (Client Hints) с серверной нормализацией.
7. **Нет обработки ботов** на уровне отчёта: категория `bot` определяется, но из показателей не исключается.

## Возможные доработки

| Идея | Что меняется |
|---|---|
| SQLite вместо JSON | новый класс-хранилище с той же сигнатурой (`addEvent`, `endSession`, `reset`) + SQL-агрегаты |
| Cookie/серверная идентификация | выдача `Set-Cookie` с `visitorId`, поддержка `SameSite` |
| HTTPS | `https.createServer` с самоподписанным сертификатом (для демонстрации на Аврора нужно будет принять сертификат в браузере) |
| Автореферралы и воронка | события уже содержат `referrer` → построить переходы «страница → страница» |
| Уведомления о новых сообщениях формы | WebSocket/SSE вместо автообновления по `setInterval` |
| Аутентификация дашборда | токен в заголовке + простая страница входа |
| Тесты графиков | сравнение эталонного PNG (node-canvas) вместо проверки «canvas инициализирован» |
